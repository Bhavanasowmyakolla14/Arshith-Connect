# Arshith Connect

Independent employee management and attendance portal for Arshith Connect.

## Requirements

- Node.js 20+
- A Supabase project

## Setup

1. Copy `backend/.env.example` to `backend/.env` and set the Supabase project URL, anon key, and service-role key. Keep the service-role key server-side.
2. Copy `frontend/.env.example` to `frontend/.env` and set `VITE_SUPABASE_URL` to your Supabase Project URL and `VITE_SUPABASE_ANON_KEY` to your anon/publishable key. Never put the service-role key in the frontend.
3. For a brand-new database only, run `database/schema.sql` in the Supabase SQL Editor. Do not run that fresh-install schema against the existing Arshith Connect database. For the existing database, `database/migrations/20261112_existing_supabase_schema.sql` was applied earlier. Apply `database/migrations/20261112_employee_account_constraints.sql` to enforce case-insensitive uniqueness for employee emails and employee codes and support mandatory first-login password changes when invitation email delivery is unavailable. Apply `database/migrations/20261112_chat_and_selfie_verification.sql` to add private chats with database-level row/storage security, realtime message publication, profile pictures, private chat uploads, and attendance selfie storage. The migration keeps both storage buckets private, uses restrictive storage policies, revokes only the `anon` attendance-table grant, and adds nullable `attendance.selfie_path` without changing existing attendance rows. The existing hourly update table is `hourly_work_updates`; no migration to create or alter an `hourly_updates` table is needed.
4. Create the first admin user in Supabase Auth, then create its profile in the SQL Editor (replace the email and name):

   ```sql
   insert into public.profiles (id, email, full_name, role)
   select id, email, 'Arshith Connect Admin', 'admin'
   from auth.users where email = 'admin@your-company.com'
   on conflict (id) do update set role = 'admin';
   ```

5. From the project root, run `npm install`, `npm install --prefix frontend`, `npm install --prefix backend`, then `npm run dev`.

The frontend runs on port 5173 and the API on port 5000. Admins invite employee accounts from the Employees page. Invite links let each employee set their own password; password resets are available from the sign-in page. Supabase Auth handles passwords; this app never stores them.

## Important behavior

- Login and logout timestamps are generated by PostgreSQL. Sessions left open are marked `incomplete` when a later login is recorded; no logout time is fabricated.
- External meeting links open without marking someone as joined. An admin can record a verified join time in the meeting participant list.
- Hourly reminders are calculated from attendance check-in and each employee's configured schedule. Missing updates are displayed as due/overdue slots and never inserted as submissions.
- Employee schedules default to `Asia/Kolkata`; admins can change each employee's time zone in the Employees page.
- Chat file and image attachments are limited to 10 MB per file. Chat conversations and private media are protected by Supabase RLS; admins can monitor conversations, while employees can access only conversations they belong to.
- Employees must allow camera access and capture a selfie before checking in. Selfies are stored privately with attendance and are viewable only by the employee and administrators.
- Configure Supabase Auth email delivery and the allowed redirect URLs (`http://localhost:5173/**` and `http://localhost:5174/**`) in the Supabase dashboard before inviting users. Vite uses port 5174 if port 5173 is already occupied.
- Vite loads frontend variables from `frontend/.env`; restart the frontend dev server after changing them.
